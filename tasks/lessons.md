# 经验教训库

## P2 - 一般

### L001: HANDOFF 中「服务运行中」声称必须在启动项目前实测
- **场景**: 2026-07-23 按 HANDOFF.md 汇报进度时，文档声称「后端/前端服务运行中」。
- **问题**: 实际 Docker Desktop 未启动，`cost-postgres` 容器不可达，前后端端口均无响应。
- **根因**: HANDOFF 为交接文档，状态描述基于作者本地当时状态，不会随环境变化自动更新。
- **解决方案**: 每次汇报运行状态前，用 `curl http://localhost:3000/health` 和 `curl http://localhost:5174` 实测，不盲信文档。
- **关键词**: ["HANDOFF", "服务状态", "本机核验", "Docker"]

### L002: 未提交改动文件数可能远超文档所列
- **场景**: 2026-07-23 HANDOFF.md 列出货「13 个文件」待提交。
- **问题**: `git status --short` 实际显示 25 个已修改文件，含 7 个后端测试文件、额外前端文件等未在清单中。
- **根因**: 文档清单为人工维护，容易遗漏测试文件、配置文件或后续追加修改。
- **解决方案**: 提交前用 `git status --short` 重新生成完整文件清单，与文档逐项核对。
- **关键词**: ["git status", "提交清单", "HANDOFF"]

### L003: 数据库断开后前端列表空白可能是 React Query 缓存
- **场景**: 2026-07-23 数据库恢复后，dashboard 能加载报价单，`成本记录` 页却显示 0 条。
- **问题**: 数据库不可达期间，React Query 可能缓存了空/失败状态；不同页面使用不同 queryKey，缓存状态不共享。
- **根因**: React Query 默认会复用缓存数据，即使数据源已恢复，未触发重新获取的页面仍显示旧状态。
- **解决方案**: 排查时先让测试者执行 `Ctrl+F5` 硬刷新或清理 localStorage 后刷新；若恢复则确认为缓存问题，非代码 bug。
- **关键词**: ["React Query", "缓存", "空列表", "数据库恢复"]

## Insights - 洞察

### I001: 旧报价单数据可能存在与当前计算逻辑不一致的字段
- **场景**: QT-2026-0004 的 `saleType` 为 `export`，但保存了 ¥4,770.91 的增值税。
- **洞察**: 当前 `cost-calculator.ts` 已对外销免征 VAT，但历史数据可能按旧逻辑保存。展示旧数据时需考虑是否重新计算或标注。
- **关键词**: ["报价单", "VAT", "export", "历史数据"]

### I002: 报价单总价显示需明确数量上下文
- **场景**: dashboard 显示 ¥26,070、¥41,470.21，用户感觉价格过高。
- **洞察**: 该数值为 1000 件总成本，单价分别为 ¥26.07/件、¥41.47/件。UI 未突出「总价/数量」关系时易造成误解。
- **关键词**: ["报价单", "总价", "单价", "UI"]
